## 1. REGISTRO DE USUARIO

### Pruebas realizadas

- **API POST /api/auth/register** con usuario test.demo@playpredict.local → 201 Created, token JWT, rol PLAYER ✅
- **API POST /api/auth/login** con el mismo usuario → 200 OK, token JWT ✅
- **Navegación tras registro**: el frontend redirigía a `/competitions` (ruta admin) en vez de `/` (dashboard player)

### Bug encontrado y corregido

**RegisterPage.tsx** siempre navegaba a `/competitions` sin importar el rol del usuario registrado. Como los nuevos usuarios siempre son PLAYER, debían ir al dashboard de jugador (`/`).

**Corrección:** `navigate('/competitions')` → `navigate(response.user.roles.includes('ADMIN') ? '/competitions' : '/')` (igual que LoginPage).

**Archivo modificado:** `frontend/src/pages/RegisterPage.tsx`

## 2. CREACIÓN DE LIGA DE AMIGOS

### Pruebas realizadas

- **API GET /api/competitions** → 2 competencias activas (Liga Profesional, Copa Libertadores) ✅
- **API GET /api/competitions/1/editions** → 1 edición activa (Clausura 2026) ✅
- **API GET /api/editions/1/rounds** → 5 fechas ✅
- **API POST /api/leagues** con RoundRange (Fecha 2 → Fecha 4) → 201 Created, id=3, inviteCode=Q74YT7LZ ✅
- **API GET /api/leagues/mine** → la liga aparece inmediatamente ✅
- **API POST /api/leagues** con roundFromId=4, roundToId=2 (inválido) → 400 Bad Request "La Fecha inicial no puede ser posterior a la Fecha final." ✅

### Bug encontrado y corregido

**LeagueCreatePage.tsx** no tenía validación frontend de `fecha inicial > fecha final`. El backend lo rechazaba, pero el usuario no recibía feedback visual hasta enviar el form.

**Corrección:** Se agregó validación en `handleSubmit` que compara `fromRound.order > toRound.order` antes de enviar, mostrando el mismo mensaje del backend.

**Archivo modificado:** `frontend/src/pages/LeagueCreatePage.tsx`

### Regla confirmada

Una Liga puede abarcar desde 1 fecha en adelante. El hint del frontend ya lo dice: "Podés elegir la misma fecha como inicial y final para crear una Liga de una sola fecha." No hay mínimos artificiales.

## 3. CÓDIGO DE INVITACIÓN

### Pruebas realizadas

- La liga creada devuelve `inviteCode: "Q74YT7LZ"` ✅
- Se muestra en el tab "Resumen" solo si `league.isCreator && league.inviteCode` ✅
- Botón "📋 Copiar código" con feedback "✓ Copiado" por 2 segundos ✅

### Mejora aplicada

**LeagueDetailPage.tsx** `handleCopyCode` no tenía `.catch()` en `navigator.clipboard.writeText`. Si el clipboard API fallaba (contexto no seguro, permisos), el botón quedaba silencioso.

**Corrección:** Se agregó fallback con `document.execCommand('copy')` vía textarea temporal para garantizar que el código se copie incluso si el Clipboard API no está disponible.

**Archivo modificado:** `frontend/src/pages/LeagueDetailPage.tsx`
